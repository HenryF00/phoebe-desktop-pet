# Codex 委托（1.9.0）

## 怎么用

1. 单击洛琪希打开输入框。支持 **Command-V** 或右键粘贴文字；复制截图后粘贴，会作为图片附件加入下一次任务（最多四张，每张 20 MB）。输入框仍只有文字和麦克风。
2. **右键洛琪希 → 选择 Codex 项目**，选择已经保存在 Codex 中的本地项目。输入框提示会显示项目名，再输入需求并回车。也可以在输入框的右键菜单中选择项目。
3. 没有项目的研究任务：选择 **联网分析 / 委托任务**，或直接输入 **委托：分析英伟达最近的财报，注明资料日期和来源**。部分明确的“帮我查……”或股票查询也会走委托；最明确的入口是“委托：”。
4. 洛琪希确认已交给 Codex 后，任务在后台执行。项目／任务模式会保持；想继续闲聊，在右键菜单中选择 **普通聊天**。
5. 执行中人物右上角显示蓝色转圈，完成后变蓝点；默认等当前聊天结束后自动打开小黑板并讲重点。双击人物 → 任务与小黑板，可以改为只亮蓝点、点击查看。**右键 → 选择 Codex 项目 → 查看委托任务…** 可查看完整结果、工作目录、请求授权、回答问题、取消或继续任务。结果也保存到聊天记录，双击气泡查看。

项目选择绑定真实项目 ID 与路径，每次提交由公开接口重新核对。项目任务在选中的现有目录执行，保留已有项目指令和未提交工作；没有项目时，每个委托使用独立的本地工作目录。应用本身不会自动提交、推送或部署。

## 能力与边界

- 普通聊天仍使用隔离的轻量通道；委托使用独立 Codex App Server，沿用本机已登录 ChatGPT 账号。即便闲聊选择 DeepSeek，委托仍交给 Codex。
- 已验证命令执行、文件写入及读回、内置联网搜索；任务通道继承本机可用的技能与 MCP 配置。没有把聊天通道的“禁用所有工具”设置带入任务。
- 任务默认使用 workspace-write 与 on-request。需要额外授权时，显示这次操作的完整详情，由用户允许或拒绝，不做静默自动批准。用户问题按原请求 ID 回传。
- **不是桌面 Codex 所有功能的完整镜像**：桌面专用工具、部分 MCP 交互、远程／云项目不保证可用。未知交互请求会明确返回不支持，不假装执行。股票分析不代下单。
- 后台执行时不用打开气泡，但桌宠应用需要保持运行。退出后未完成任务标为中断，下次打开可在列表中继续；不会在重启时未经点击就重新执行写操作。
- 委托串行执行，后续任务排队。停止聊天／关闭气泡不取消委托，取消需从任务列表操作。
- “本轮已结束”只代表模型本轮结束，不代表业务目标或所有检查成功。实际未完成事项保留在结果正文。

## 存储与通知

任务记录存于 `runtime/tasks/<id>.json`，权限 0600；截图位于 `runtime/attachments/`，被 Git 忽略，随用户发起的任务传给模型。尚未发送的截图可在输入框右键菜单中移除。

任务过程不逐条插入聊天字幕或朗读；只确认委托、提示需要处理的请求。最终结果另存小黑板与聊天记录，重点讲解排在当前聊天之后，手动模式不自动播放。小黑板文字与聊天字幕分开维护，播放不会回滚字幕。

## 接口与实现

使用本机生成的公开协议 schema：project/list、thread/start、thread/resume、turn/start、turn/interrupt，以及任务事件和授权回调。没有读取桌面应用私有数据库或访问内部 IPC。参考 [官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)。

本机的 `codex` 是桌面应用内置二进制的符号链接。任务启动先解析真实二进制路径，并将同目录放进子进程 PATH，以找到相邻的 `codex-code-mode-host`。只给委托进程启用独立内置搜索，没有修改全局 Codex 配置。

## 验证

- Python：任务路由、审批请求所有权与重复回复拒绝、并发待批请求、完成状态、取消后的迟到事件、持久化、附件路径边界，以及原有聊天回归。
- 原生界面：私有测试剪贴板的 Command-V 文字／截图粘贴、附件移除、Command-A、项目菜单、任务结果、允许／拒绝回传；保留原有字幕与音频回归。
- `qa/delegation-smoke.json`：真实 Codex 在专属测试目录写入 `ROXY_TASK_OK`、命令读回确认，内置 web 检索并核实官方文档。早期组件路径故障已经修复后重新验证。
- `qa/delegation-ui/`：任务列表与操作授权窗口的浅色／深色渲染检查。
