# 洛琪希语音聊天 · 1.6.1

## 现在怎么使用

打开 `dist/Roxy HD.app`，**单击洛琪希**展开身旁的半透明单行输入栏，再次单击人物收起。拖动人物时输入栏和字幕一起移动，靠近屏幕边缘自动调整位置。

1. **打字**：输入文字，回车发送。输入框没有矩形焦点高亮，下排状态、停止和关闭按钮已移除。
2. **说话**：直接按住右侧麦克风录音，松开发送；录音时图标变红。首次允许系统麦克风权限后再次按住。键盘聚焦麦克风后可用空格开始或结束，每次最长 60 秒。
3. **设置**：双击人物打开设置，字幕可选中文 / English；声音可选日语 / 中文 / English。两者互相独立，默认仍是中文字幕、日语声音。选择后点“保存”，或“保存并试听声音”。
4. **模型**：选 Codex 使用已登录的 ChatGPT 订阅，可留空模型名以跟随默认模型，也可填写具体名称。选 DeepSeek 后填写模型与 API Key，默认 `deepseek-v4-flash`，也提供 `deepseek-v4-pro`。密钥仅持久化到本机 macOS 钥匙串，空白保留旧密钥，可主动清除；不会写进项目、偏好设置或日志。
5. **聊天记录**：双击字幕气泡、气泡里的“你”或洛琪希文字，打开可滚动、复制的记录窗口；右键人物菜单也有“查看聊天记录”。双击人物仍打开设置。输入发出后，本轮文字保留在气泡上方；语音识别完成后显示实际转写，直到下一轮输入替换。
6. **停止**：输入栏按 Esc，或再次单击人物收起。右键人物菜单也可停止声音。新消息会打断上一条回复。设置中“新对话”清空模型的当前上下文，保留可查看的历史记录。
7. **任务播报**：菜单栏或右键人物菜单开关；字幕和声音使用保存的语言设置。关闭播报仍可以在设置中主动试听。

Codex 使用本机 `codex` 的 ChatGPT 登录，由官方 App Server 管理凭证，不读取或复制登录 token。未登录时在终端运行 `codex login`。Codex 聊天消耗共享额度；DeepSeek 聊天按其 API 计费。本地识别和合成不调用付费音频 API。

DeepSeek 使用[官方 JSON 输出接口](https://api-docs.deepseek.com/guides/json_mode/)和 SSE 流，关闭额外思考，不提供工具。密钥仅在选用 DeepSeek 时由原生程序读取，经私有 stdin 传给聊天进程，再以 HTTPS 发送到 `api.deepseek.com`；输入转写和最近聊天文字发送给所选模型。尚未填入真实 DeepSeek 密钥，当前仅通过模拟接口测试，不能视为真实账号调用验收。

## 任务播报还需要一次信任

2026-09-08 用官方 `hooks/list` 查询：7 个 Roxy Hooks 均 enabled=true、trustStatus=untrusted。因此真实任务事件尚未送达，不能把试听或模拟事件测试当作真实联动已启用。

在终端启动 `codex`，输入 `/hooks`，检查来源 `~/.codex/hooks.json`，信任其中指向 `~/Library/Application Support/RoxyHD/bridge.py` 的 Roxy Hooks。之后在 Codex 发起一次任务，观察桌宠窗口是否显示“已收到 Codex 事件”。如果当前桌面任务仍未刷新 Hooks，请新开任务或重启 Codex 后再试。

这是 Codex 官方要求的精确定义信任，不是模型调用收费确认。程序没有绕过或修改 Hooks 信任记录。[官方 Hooks 信任说明](https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks)

播报含义：

- `Stop`：本轮处理结束，请查看结果。不声称整个目标一定成功完成。
- 等待用户操作：提示查看 Codex。
- `Interrupt/SessionEnd` 不播报成功；不会每个工具调用都说话。启动时不重播旧事件，同一任务同一轮同类提醒去重；一个任务结束时不会被另一项仍在运行的任务遮住。

## 实现与验证

链路为本地 PCM16 录音 → MLX Whisper → 所选模型文字增量 → 所选字幕/语音语言成对句子 → 本机 GPT-SoVITS v2ProPlus 流式推理 → PCM16/32 kHz 音频块 → 原生 AVAudioEngine/AVAudioPlayerNode 连续调度。使用 streaming_mode=2，保留上游重叠拼接；不再等待整句 WAV。语音句子文本仍需先生成，随后合成和播放重叠进行。当前不支持免提抢话/回声消除。固定提示复用缓存 WAV，与流式播放器互斥排队，避免叠音。停止会立即停止播放器，并取消模型生成、丢弃迟到结果；已经进入本地 TTS 的计算可能仍需跑完，但不会继续播放旧回复。

每个回答使用环境访问关闭的临时 Codex 对话，最多带入最近 10 轮的文字历史。关闭 MCP、插件、浏览器、Shell、多代理、记忆和该聊天进程自身 Hooks，不关联或修改实际工作任务。聊天模型不会读到工作任务内容。固定任务提示不额外调用模型。

麦克风音频只在本机识别；转写文字和聊天上下文发给所选模型。录音完成识别或出错后删除。源码与模型路径写入本机 App 资源，移动项目需重新构建。

### 中英文发音质量处理

## 1.6.0 播音字幕同步与记录

此前模型的后续 `delta` 会覆盖还在播放的那句字幕，属于字幕时间线错误。现在第一段音频开始前可以显示流式文字；开始播放后，字幕由音频分段的 `onBegan` 驱动，等实际 `.dataPlayedBack` 完成才进入下一句。全部播放结束后显示完整回答。任务播报会等当前回答结束，避免在分句合成间隙插入；提醒错误不会覆盖正在播放的字幕。

“你”区域保留最近一轮发送内容，包括本地 ASR 的实际识别文字，洛琪希回复时也保留。长消息在气泡中截取展示，双击查看全文。聊天记录中的增量继续更新；向上翻记录时不强制滚回底部。

记录从 1.6.0 起存为本项目 `runtime/chat-history.rtf`，本机用户读写权限 0600，Git 忽略，可重启后打开查看。旧版只存内存、已经退出的记录无法补回。查看记录不会把整份存档发送给模型：模型上下文仍仅为当前对话最近 10 轮。“新对话”保留存档并插入分隔记录。

验证：`tests/CaptionTimingHarness.swift` 在修复前通过实际静音音频引擎复现“第一句未播完就显示第二句”，修复后通过首句锁定、下一句播放后切换、结束后全文显示与提醒错误不抢字幕；`tests/ChatHistoryHarness.swift` 验证打字/ASR 保留、本机记录保存读取、文件权限、新对话保留存档、双击处理及可选择的历史窗口；原有原生聊天回归通过。明暗外观与长内容截图见 `qa/chat-history-ui/`。


## 1.6.1 修正文字回退

1.6.0 把语音开始前的流式全文、播放中的单句字幕、播完后的全文混用，导致文字出现“全文 → 单句 → 全文”回退。现改为正文只由模型增量追加，音频开始、分句变化、播放结束均不再覆盖正文。音频仍逐句顺序播放。任务提醒追加在正文下面，播放结束也不撤掉后恢复正文；输入保留和双击记录入口不变。

`CaptionTimingHarness` 使用实际静音音频队列复现了两句文字已显示、首句声音开始时正文退回一句；修复后验证首音、后续增量、切句、模型完成和播放结束全程保持已显示文字，同时核对音频实际切句顺序。此前 1.6.0 的按句替换字幕说明已被本节取代。
