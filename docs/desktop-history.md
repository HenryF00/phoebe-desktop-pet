## 跟随 Codex 任务

右键菜单的 **跟随 Codex 任务** 默认开启。联动启用后：

- 提交任务、执行工具：思考工作。
- 请求操作权限、同步等待用户输入：等待。
- 本轮结束：查看结果 8 秒，再回待机。
- 中断或关闭任务：回待机。
- 多个任务并行时，优先显示需要操作的任务，其次显示正在运行的任务。手动点击或选择动作暂时覆盖联动，随后恢复。

已在本机安装 `~/Library/Application Support/RoxyHD/bridge.py` 和 `~/.codex/hooks.json`，原来没有 Hooks 配置。脚本只在本机保存事件类别、匿名会话标识、轮次标识和时间，不保存提示词、工具参数、回复或会话正文，也不联网。配置副本为 `codex-hooks.json`。

**尚需首次信任 Hooks，真实任务联动未完成端到端验证。** 官方要求新定义由用户审核信任：

1. 打开上一级的 `开启Codex联动.command`，它只启动本机随桌面 App 安装的 Codex CLI，并显示操作说明。
2. 在 CLI 输入 `/hooks`，查看来源为 `~/.codex/hooks.json`、命令指向 `RoxyHD/bridge.py` 的七项定义，信任它们。
3. 回到 Codex 开始下一轮任务。桌宠右键菜单会显示“Codex：正在处理任务”。如果已有任务未加载新配置，可在合适时重新打开 Codex 后再试。

这是 Codex 的首次 Hooks 信任要求，不是桌宠额外设计的确认步骤。参考：https://learn.chatgpt.com/docs/hooks

同步依据本地 Hooks；不读取 Codex 私有数据库，不控制 Codex UI。云端、其他机器的任务不在范围内。30 分钟未更新的状态会过期，避免异常退出后永久卡在工作姿势。Hooks 的 Stop 表示本轮结束，不能可靠区分任务成功与失败；失落动作仍可手动选择。异步问题接口不保证等待期间一直显示等待。

联动开启时不再随机播放“工作/查看结果”类动作，避免误解任务状态。关闭联动后保留随机轻动作和视线互动。
